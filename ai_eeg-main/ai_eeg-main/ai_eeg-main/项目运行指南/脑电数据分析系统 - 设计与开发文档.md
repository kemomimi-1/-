# 脑电数据分析系统 - 设计与开发文档

## 1. 项目概述

### 1.1 项目简介

本项目是一个脑电数据采集与智能分析平台，基于Spring Boot后端框架搭建，前端采用原生HTML/CSS/JavaScript实现。系统通过UDP协议接收来自OpenBCI GUI的实时脑电数据流，将数据持久化到InfluxDB时序数据库中，同时集成了阿里云通义千问大模型（qwen-max），结合自研的MCP（Model Context Protocol）工具集，对脑电数据进行多维度的智能分析。

用户可以在Web端完成设备连接、数据采集、AI对话问答、实时频谱弹幕监测、对话历史管理等操作，整个系统实现了从数据采集到智能分析的完整闭环。

### 1.2 功能模块划分

系统按业务划分为以下功能模块：

| 模块 | 说明 |
|:---|:---|
| 用户认证模块 | 注册、登录、退出、Session管理 |
| EEG连接管理模块 | UDP端口分配、数据接收、连接状态监控 |
| 数据存储模块 | InfluxDB时序数据写入与查询、MySQL关系数据管理 |
| AI对话模块 | 集成通义千问大模型，支持MCP工具调用和SSE流式输出 |
| 实时弹幕分析模块 | 周期性频谱分析，通过WebSocket推送弹幕到前端 |
| 对话历史模块 | 对话会话管理、收藏、标题编辑、批量操作 |
| EEG会话管理模块 | 数据传输会话的全生命周期管理 |
| MCP分析服务模块 | 数据摘要、特征提取、多会话对比、研究导向分析 |
| 端口池管理模块 | 端口分配策略、健康监测、管理员操作 |

## 4. 数据库设计

### 4.1 MySQL数据库（eeg_platform）

项目使用JPA的 `ddl-auto: update` 策略自动建表，共包含4张业务表。

#### users 表 — 用户信息

| 字段 | 类型 | 约束 | 说明 |
|:---|:---|:---|:---|
| id | BIGINT | 主键，自增 | 用户ID |
| username | VARCHAR(20) | UNIQUE, NOT NULL | 用户名，6-20位字母数字 |
| password | VARCHAR(255) | NOT NULL | BCrypt加密后的密码 |
| raw_port | INT | — | 当前分配的原始数据端口号 |
| filt_port | INT | — | 当前分配的滤波数据端口号 |
| band_port | INT | — | 当前分配的频谱功率端口号 |
| is_active | BOOLEAN | 默认false | 用户当前是否有活跃连接 |
| last_connection | DATETIME | — | 最后一次连接时间 |
| created_at | DATETIME | 自动生成 | 注册时间 |
| updated_at | DATETIME | 自动更新 | 记录更新时间 |

#### eeg_sessions 表 — 数据传输会话

这张表记录每次EEG数据传输会话的完整信息，包括三路数据流（原始/滤波/频谱功率）各自独立的状态跟踪。

| 字段 | 类型 | 说明 |
|:---|:---|:---|
| id | BIGINT | 会话ID |
| user_id | BIGINT | 所属用户 |
| session_start_time / session_end_time | DATETIME | 本地时间 |
| session_start_time_utc / session_end_time_utc | DATETIME | UTC时间（用于数据查询对齐） |
| user_timezone | VARCHAR(50) | 用户时区，如 `Asia/Shanghai` |
| session_status | ENUM | `ACTIVE` / `COMPLETED` / `INTERRUPTED` / `ERROR` |
| raw_stream_status / filt_stream_status / band_stream_status | ENUM | 各数据流状态：`WAITING`/`ACTIVE`/`PAUSED`/`COMPLETED`/`ERROR` |
| raw_stream_total_packets / filt_stream_total_packets / band_stream_total_packets | BIGINT | 各数据流累计接收的包数 |
| raw_stream_start_time_utc / filt_stream_start_time_utc / band_stream_start_time_utc | DATETIME | 各数据流首包时间 |
| raw_stream_last_packet_time_utc / ... | DATETIME | 各流最后一个包的时间 |
| raw_port / filt_port / band_port | INT | 分配的端口号 |
| total_duration_seconds | BIGINT | 会话总时长 |
| notes | VARCHAR(1000) | 备注 |

设计时对开始/结束时间同时保存了本地时间和UTC时间两个版本，UTC用于和InfluxDB中的时序数据对齐查询，本地时间用于前端展示。

#### conversation_history 表 — 对话历史

| 字段 | 类型 | 说明 |
|:---|:---|:---|
| id | BIGINT | 记录ID |
| user_id | BIGINT | 所属用户 |
| conversation_session_id | VARCHAR(100) | 对话会话ID，同一次对话的多轮问答共享这个ID |
| user_query | TEXT | 用户输入的问题 |
| ai_response | LONGTEXT | AI的回答 |
| conversation_timestamp | DATETIME | 对话发生的时间 |
| eeg_session_id | BIGINT | 关联的EEG会话ID（可选） |
| response_tokens | JSON | token用量信息 |
| processing_duration_ms | BIGINT | 处理耗时，单位毫秒 |
| used_mcp_tools | BOOLEAN | 这次回答是否调用了MCP工具 |
| tools_used | JSON | 调用了哪些工具，JSON格式 |
| query_category | VARCHAR(50) | 查询分类（数据查询/统计分析/EEG分析等） |
| user_rating | INT | 用户评分，1-5星 |
| is_bookmarked | BOOLEAN | 是否被收藏 |
| session_title | VARCHAR(200) | 对话会话标题 |

**索引：**
- `(user_id, conversation_session_id, created_at DESC)` — 查某次对话的所有消息
- `(user_id, created_at DESC)` — 查用户最近的对话
- `(conversation_session_id, created_at ASC)` — 按时间正序拉取对话

#### barrage_messages 表 — 弹幕消息

每条弹幕记录了一次频谱分析的完整结果，包括分析文本、精神状态、频段功率快照等信息。

| 字段 | 类型 | 说明 |
|:---|:---|:---|
| id | BIGINT | 弹幕ID |
| user_id | BIGINT | 所属用户 |
| content | VARCHAR(500) | AI生成的分析描述文本 |
| primary_state | ENUM | 精神状态（见下方枚举说明） |
| alert_level | ENUM | 警告级别：NORMAL / ATTENTION / WARNING / CRITICAL |
| alpha_value ~ gamma_value | DOUBLE | 分析时的五频段功率快照值 |
| data_start_time / data_end_time | DATETIME | 分析所用数据的时间范围 |
| sample_count | INT | 参与分析的样本数量 |
| confidence_score | DOUBLE | 置信度得分 |
| dominant_frequency | VARCHAR(100) | 主导频段 |
| recommendation | VARCHAR(200) | 状态建议 |
| created_at | DATETIME | 弹幕创建时间 |

**精神状态枚举（MentalState）：**

| 值 | 含义 | 判断依据 |
|:---|:---|:---|
| DEEP_RELAXATION | 深度放松 | 归一化Alpha > 0.5 |
| RELAXED | 放松 | 归一化Alpha > 0.35 |
| FOCUSED | 专注 | 归一化Beta > 0.4 |
| STRESSED | 紧张 | 归一化Beta > 0.6 |
| ALERT | 警觉 | 归一化Gamma > 0.4 |
| DROWSY | 困倦 | 归一化Delta > 0.4 |
| MEDITATIVE | 冥想 | Theta + Alpha组合主导 |
| CREATIVE | 创造性状态 | 归一化Theta > 0.3 |
| HYPERACTIVE | 过度活跃 | 归一化Gamma > 0.6 |
| UNBALANCED | 状态失衡 | 多频段同时异常活跃 |

### 4.2 InfluxDB（时序数据）

InfluxDB中存储了3个Measurement，由 `EEGDataReceiver` 解析UDP数据包后写入：

| Measurement | 说明 | 字段 |
|:---|:---|:---|
| `timeseriesraw` | 原始8通道EEG数据 | time, user_id, channel(1-8), sample, value |
| `timeseriesfilt` | 滤波处理后的EEG数据 | time, user_id, channel(1-8), sample, value |
| `avg_band_power` | 各频段平均功率 | time, user_id, band(alpha/beta/theta/delta/gamma), value |

InfluxDB的连接通过 `InfluxDBService` 封装，使用Spring WebClient调用InfluxDB 3.2.1的HTTP API，查询语法为标准SQL。

## 5. 核心业务流程

### 5.1 EEG数据采集流程

```
1. 用户登录 → POST /api/auth/login
2. 请求连接 → POST /api/connection/request
   ├─ EnhancedPortAllocationService 从端口池分配3个UDP端口
   ├─ EEGSessionService 创建一条ACTIVE状态的EEG会话记录
   └─ EEGDataReceiver 启动3个UDP Socket监听
3. 用户在OpenBCI GUI中配置IP和3个端口号，启动数据传输
4. EEGDataReceiver 持续接收UDP数据包
   ├─ 解析数据内容
   ├─ 以Line Protocol格式写入InfluxDB
   └─ 更新EEG会话的包数和数据流状态
5. 用户操作断开连接 → POST /api/connection/disconnect
   ├─ 停止UDP监听
   ├─ 将EEG会话状态改为COMPLETED，记录结束时间
   └─ 释放端口回到端口池
```

### 5.2 AI对话流程

```
1. 用户发送问题 → POST /api/ai/query/stream
2. AIQueryController 构建上下文：
   ├─ 分析查询复杂度（关键词匹配）
   ├─ 确定工具协作策略和推荐的MCP工具列表
   ├─ 拉取当前活跃会话信息和用户统计
   └─ 拼接场景化系统提示词
3. 调用通义千问API（开启Function Calling模式）
4. AI可能自主决定调用MCP工具：
   ├─ MCPToolRegistry 根据工具名执行对应逻辑
   ├─ 工具从InfluxDB/MySQL获取数据
   └─ 将工具结果返回给AI继续生成
5. AI生成的文本通过SSE逐字推送给前端
6. 完成后将整轮对话保存到conversation_history表
```

### 5.3 实时弹幕分析流程

```
1. 用户点击"开始分析" → POST /api/realtime-analysis/start
2. RealTimeSpectrumAnalysisService 将用户加入活跃用户集合
3. 定时任务每7秒触发一次（@Scheduled）：
   ├─ 从InfluxDB查询该用户最近1分钟的avg_band_power数据
   ├─ 计算五频段（Alpha/Beta/Theta/Delta/Gamma）均值
   ├─ 归一化处理，消除个体功率差异
   ├─ 根据阈值判断精神状态和警告级别
   ├─ 调用AI生成一段自然语言的分析描述
   ├─ 创建Barrage记录保存到MySQL
   └─ 通过WebSocket推送给前端，前端以弹幕动画形式展示
4. 用户点击"停止分析" → POST /api/realtime-analysis/stop
```

## 6. MCP工具集设计

### 6.1 概述

MCP（Model Context Protocol）工具集是本系统的一个设计，目的是让AI大模型在对话过程中能够自主访问系统中的脑电数据。MCPToolRegistry中注册了15个工具，每个工具对应一个可调用的Function，当AI判断需要获取数据时，会通过Function Calling机制调用这些工具。

### 6.2 工具列表

**基础工具：**

| 工具名 | 功能 |
|:---|:---|
| `getActiveSessionContext` | 获取用户当前活跃的EEG会话上下文信息 |
| `queryLatestBandPowerData` | 查询最新的频段功率数据 |
| `generateComprehensiveSessionSummary` | 对一个会话的数据生成多层次的统计摘要 |

**辅助工具：**

| 工具名 | 功能 |
|:---|:---|
| `getSessionDetails` | 获取某个会话的详细信息 |
| `monitorSignalQuality` | 评估当前信号质量 |
| `getUserStatistics` | 获取用户的使用统计数据（总会话数、平均时长等） |
| `queryRawEEGData` | 查询原始EEG时序数据 |
| `queryFilteredEEGData` | 查询滤波后的EEG数据 |
| `assessSessionDataVolume` | 评估某个会话的数据量 |

**高级工具：**

| 工具名 | 功能 |
|:---|:---|
| `compareSessionDataQuality` | 对比多个会话的数据质量 |
| `querySessionsByConditions` | 按条件（时间范围、状态等）筛选会话 |
| `getSessionTechnicalSpecs` | 获取会话的技术参数（采样率、通道数等） |
| `getSessionHistory` | 获取用户的会话历史列表 |
| `executeCustomQuery` | 执行自定义SQL查询（AI自主构造查询语句） |
| `queryDataByTimeRange` | 按时间范围查询数据 |

### 6.3 工具协作策略

系统会根据用户输入的查询内容自动评估复杂度，决定推荐多少个工具给AI：

| 复杂度 | 预期工具数 | 典型场景 |
|:---|:---|:---|
| 低 | 1-2个 | "我现在什么状态？" |
| 中 | 2-4个 | "详细分析一下最近的数据" |
| 高 | 3-6个 | "对比今天和昨天的专注度" |
| 很高 | 5-10个 | "全面评估我所有会话的数据质量和趋势" |

查询复杂度的判断基于关键词匹配，比如出现"对比"、"比较"会触发COMPARISON模式，出现"全面"、"详细"会触发COMPREHENSIVE模式。

| temperature | 0.1 | 低温度值，让输出更稳定一致 |
| max-tokens | 8000 | 单次回复最大token数 |
| timeout | 300秒 | 请求超时（AI调用多个工具时可能比较耗时） |
| max-tool-calls | 14 | 单次对话中AI最多可以调用14个工具 |
| max-retries | 3 | 调用失败自动重试次数 |

系统中有两个服务负责调用AI：
- `AIModelService`：负责非流式调用，等AI生成完整回复后一次性返回
- `AIStreamService`：负责SSE流式调用，AI生成过程中逐字推送给前端

### 7.2 InfluxDB HTTP API

`InfluxDBService` 通过Spring WebClient调用InfluxDB 3.2.1的HTTP API进行数据查询和写入：

- **查询**：使用标准SQL语法，通过HTTP POST发送到InfluxDB的查询端点
- **写入**：`EEGDataReceiver` 解析UDP数据包后，拼接成InfluxDB Line Protocol格式写入

### 7.3 OpenBCI GUI

OpenBCI GUI是脑电设备的配套软件，不涉及代码层面的集成。用户在GUI中配置系统分配的IP地址和3个端口号（分别对应TimeSeriesRaw、TimeSeriesFilt、AvgBandPower三种数据类型），选择UDP协议后即可开始向本系统发送脑电数据。

## 9. 安全设计

### 9.1 身份认证

采用基于HttpSession的会话认证机制：
- 登录成功后在Session中存储userId和username
- Session超时时间30分钟
- Cookie配置：HttpOnly=true，max-age=1800s

### 9.2 数据隔离

所有数据查询都通过userId进行过滤，用户只能访问自己的数据：
- Controller层从Session中获取userId，传递给Service层
- InfluxDB查询自动在WHERE条件中添加 `user_id = '当前用户ID'`
- 自定义SQL查询接口会强制注入user_id过滤条件，防止越权访问

### 9.3 密码安全

使用Spring Security Crypto提供的BCrypt算法对用户密码加密存储，注册时验证密码强度（8-30位，需包含字母和数字）。

### 9.4 MCP安全限制

| 限制项 | 值 |
|:---|:---|
| 自定义SQL最大长度 | 5000字符 |
| 查询超时 | 300秒 |
| 每用户请求频率 | 100次/分钟 |

## 10. 脑电频段参考

以下是系统中使用到的脑电频段定义，基于神经科学领域的通用分类标准：

| 频段 | 频率范围 | 典型含义 |
|:---|:---|:---|
| Delta (δ) | 1-4 Hz | 深度睡眠、无意识状态 |
| Theta (θ) | 4-8 Hz | 轻度睡眠、冥想、创造性思维 |
| Alpha (α) | 8-13 Hz | 清醒放松、闭眼休息 |
| Beta (β) | 13-30 Hz | 主动思考、专注工作 |
| Gamma (γ) | 30-100 Hz | 高级认知功能、跨区域信息整合 |

OpenBCI 8通道的电极位置对应关系：

| 通道 | 电极 | 脑区 |
|:---|:---|:---|
| CH1 / CH2 | Fp1 / Fp2 | 前额叶 |
| CH3 / CH4 | C3 / C4 | 中央区（运动/感觉） |
| CH5 / CH6 | P7 / P8 | 顶叶 |
| CH7 / CH8 | O1 / O2 | 枕叶（视觉区域） |
